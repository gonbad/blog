# Review the actual interaction and layout

Serve the built output, then run `python3 moom.py run verify` with BLOG_URL/PLAYWRIGHT_MODULE as documented. Dispatch to the selected project's real acceptance checks and bundle each check script with the frozen helper. Do not assume the index contains only one post. Keep checks for other published posts usable as regression checks.

An unknown project must fail with an explicit missing-checks message instead of silently running post 001's checks. Register its actual checks and freeze/migrate the revised method before calling that project verified.

For a prompt generator, verify valid and rejected input paths, absence of credential collection, invalidation of previously generated output after edits, copy/download behavior, actual command content and browser-native field keys. Offline tests must use the actual downloaded archive with networking disabled. Passing generator/browser checks is not evidence that provisioning or real account login was tested.

Inspect desktop/phone layouts and the actual failure paths. Click a control before pressing Up/Down. Preserve Space activation, horizontal tab keys, text editing, reading mode, reduced motion and direct seeking semantics. Wait for asynchronous outcomes. Review source claims and the artifact as well as test results. Record issues and feed general corrections back to this recipe or Moom.
