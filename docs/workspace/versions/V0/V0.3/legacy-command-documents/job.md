# Discover the repeated job through Project 001

Read process, profile and state. Use the owner's first real task and first intended input. Create Project 001 with `python3 moom.py new SLUG --first --title TITLE`; this resumes the existing first project when repeated. If adopting an already built project, use `new FULL-ID --adopt` and preserve its source and brief.

Capture which facts recur versus belong to this instance. Ask only unresolved choices in Markdown. Agree a small useful result, make it, and review its new decisions. Then write docs/job/definition.md, quality.md, actual procedures and workflow.json from the work performed. Choose meaningful reviewable steps, usually around ten; count is not a gate. Declare helper files/argument lists only when actually used. Never prescribe a web stack for a non-web job.

Freeze the candidate method with `moom.py freeze REVISION`; use `--evidence` only after actual approval. Pin Project 001 with `moom.py migrate REVISION --note REASON`. Synchronize native commands. Carry forward completed artifacts rather than repeating input collection or rebuilding an accepted sample. End at the next unfinished production step, showing the real artifact and short review packet.
