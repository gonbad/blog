## ۱. هرمس (Hermes Agent) — یافته‌های پژوهش

**منابع خوانده‌شده:** صفحه GitHub ریپو + `hermes-agent.nousresearch.com/docs/`

**چیست (یک جمله برای اسلاید):** ایجنت شخصیِ خودبهبودشونده، ساخته Nous Research؛ روی VPS/سرور یا حتی گوشی (Termux) می‌نشیند و از طریق CLI، دسکتاپ، تلگرام/دیسکورد/واتس‌اپ و... با آن حرف می‌زنی و برایت کار انجام می‌دهد.

**چرا مهم است برای تز ارائه:** هرمس دقیقاً همان چیزی است که کارفرما می‌گوید «آینده»: یک UX گفتگویی + ده‌ها ابزار + حافظه. و چون **MIT و چندپروایدره** است (Nous Portal، OpenRouter، OpenAI، اندپوینت شخصی)، برای مخاطب ایرانی از نظر مفهومی بهترین ویترین است: قفل به یک شرکت نیست.

**معماری برای ارائه (۵ بلوک، ساده‌شده):**
۱. **ورودی‌ها:** CLI/TUI + Gateway پیام‌رسان‌ها (تلگرام، دیسکورد، اسلک، واتس‌اپ، سیگنال و...) + cron (کار زمان‌بندی‌شده).
۲. **مغز:** هر LLM دلخواه (`hermes model` عوض می‌شود، بدون تغییر کد).
۳. **ابزارها:** ۶۰+ ابزار داخلی (فایل، ترمینال، وب، جست‌وجو، تصویر، صوت) + هر MCP سرور بیرونی.
۴. **حافظه/یادگیری (تمایز اصلی):** حافظه ماندگار + «مهارت» (Skill) که ایجنت بعد از کارهای پیچیده خودش می‌سازد و دفعه بعد بهتر انجام می‌دهد + جست‌وجوی مکالمات قدیمی + مدل‌سازی از کاربر. شعار داکس: *The only agent with a built-in learning loop*.
۵. **اجرا:** ۷ بک‌اند ترمینال (local، Docker، SSH، Daytona، Modal و...)؛ یعنی لازم نیست روی لپ‌تاپ خودت باشد — روی VPS ارزان هم کار می‌کند و با گوشی به آن پیام می‌دهی.

**نکته ظریف که باید در ارائه صادقانه گفته شود:** در ریپو دستور `hermes claw migrate` (مهاجرت از OpenClaw) هست. یعنی هرمس روی موج و استانداردهای ایجنت‌های اوپن‌سورس سوار است، نه اینکه همه‌چیز را از صفر اختراع کرده باشد. این را نقطه قوت بگو: «استانداردباز، قابل مهاجرت»، نه «جادو».

**جایگاه در جدول ابزارها:** هرمس = ایجنت **عمومی** (General-purpose). بقیه (Cursor، Claude Code و...) = تخصصی‌تر (کدنویسی). این تفکیک را در ارائه نگه دار تا مخاطب قاطی نکند.

**امنیت (۱ اسلاید لازم):** تاییدیه اجرای دستور (approval)، ایزولیشن با کانتینر، جفت‌سازی DM. چون ایجنت به فایل/ترمینال دسترسی دارد، بدون این اسلاید ارائه ناقص است.

## ۲. جو (Jev) — یافته‌های پژوهش

**منابع خوانده‌شده:** `typesafe.ai/blog/introducing-system-one-models-and-jev` + ویکی‌پدیا `Jev (AI model)` (+ نسخه فارسی با عنوان «جو»).

**چیست (دو جمله برای اسلاید):** «جو» (Jev، به نام اقتصاددان Jevons) اولین مدل از خانواده **System One** شرکت TypeSafe AI است (انتشار دسترسی محدود: ۱۵ سپتامبر ۲۰۲۶، یعنی ~۲ هفته پیش). برخلاف LLM که **متن** تولید می‌کند، جو **تصمیم تایپ‌دار با احتمال و اطمینان** برمی‌گرداند تا نرم‌افزار مستقیم مصرفش کند، نه انسان.

**سه خروجی (Primitives) — عیناً برای اسلاید:**
| خروجی | کار | برمی‌گرداند |
|---|---|---|
| Choice | انتخاب یکی از چند گزینه | گزینه + احتمال هر گزینه + اطمینان |
| Score | نمره‌دادن به وضعیت در سطوح مرتب | نمره + احتمال هر سطح + اطمینان |
| Noul | داوری بله/خیر یک گزاره | احتمال ۰ تا ۱ |

**چرا برای ارائه مهم است:** دقیقاً همان چیزی است که کارفرما در транскрипشن گفت «مدل تصمیم‌گیری». جو بهترین مثال زنده برای «دنیا فقط LLM نیست» است و تز «حلقه ایجنت» را کامل می‌کند: **LLM برای فهم/گفتگو، جو برای تصمیم سریع/ارزان داخل کد.**

**تفاوت کلیدی (جدول اسلاید):**
| | LLM معمولی | جو |
|---|---|---|
| ورودی | متن/پیام ترتیبی | state (متن/JSON) + سوال‌های تایپ‌دار |
| خروجی | رشته متنی (ممکن: توهم، امتناع، خطای تایپ) | مقدار تایپ‌دار از قبل تعریف‌شده (ادعا: بدون توهم و بدون خطای تایپ) |
| نمونه‌برداری | ترتیبی، توکن‌به‌توکن | موازی، یک‌پاس برای همه سوال‌ها |
| آموزش | RLHF/RLVR (رضایت داور انسانی / پاداش قابل راستی‌آزمایی) | RLCD (کالیبره‌بودن احتمال روی پیامد واقعی) |
| سرعت/هزینه ادعایی | ثانیه‌ها (مثلاً ۳ تا ۳۲۹ ثانیه end-to-end در بنچمارک خارجی) | ۷۰ تا ۵۰۰ میلی‌ثانیه؛ ادعای ۴۰ تا ۲۰۰ برابر سریع‌تر و ۴۰ تا ۴۰۰ برابر ارزان‌تر؛ ورودی ~۰.۰۴۲ دلار بر میلیون توکن، خروجی رایگان |
| کاربرد | چت‌بات، کوپایلت، ایجنت با انسان در حلقه | if هوشمند داخل نرم‌افزار، امتیازدهی/مسیریابی/راستی‌آزمایی، map-reduce روی داده بزرگ، کاربرد بلادرنگ (مثال نمایشی: بازی Doom با ~۱۰ کوئری/ثانیه) |

**قیدهای صداقت (حتماً در اسلاید پانوشت شود — اعتبار ارائه به همین است):**
- ادعاهای سرعت/هزینه **خوداظهاری** شرکت است روی ورک‌فلوهای تیم خودش؛ خودش می‌گوید «احتمالاً سقف واقعی» و «سوگیری ممکن». بنچمارک مستقل هنوز نیست.
- معماری دقیق، وزن‌ها و مقاله فنی منتشر نشده (فقط «ترنسفورمری، فقط داده مصنوعی»).
- سقف تعداد گزینه (cardinality) فعلاً ۲۵۵.
- پس لحن درست: «مکمل نوظهور و امیدوارکننده، نه جایگزین LLM». همین یک جمله ارائه را از تبلیغ به تحلیل تبدیل می‌کند.

## ۳. Z Code، FreeBuf و لیست نهایی ابزارها

### ۳.۱ Z Code by Z AI
- **چیست (تا حد دانش + نیاز به تایید لحظه ساخت):** عامل/محیط کدنویسی شرکت چینی **Zhipu (با برند Z AI)** روی خانواده مدل **GLM** (نسخه‌های ۴.۵/۴.۶ به بعد با تمرکز کدنویسی و ایجنت). در اکوسیستم چین رقیب Claude Code/Cursor معرفی می‌شود.
- **چرا در ارائه باشد:** ۱) مخاطب باید بداند دنیا فقط آمریکا نیست (چین هم استک کامل دارد). ۲) برای مخاطب ایرانی که با تحریم درگیر است، دانستن مسیرهای جایگزین/ارزان مهم است.
- **احتیاط:** جزئیات محصول Z Code سریع عوض می‌شود. در اسلاید فقط در سطح «چیست + مدل پایه + محلی/ابری + قیمت‌مبنا» بگو و تاریخ بزن (مثلاً «وضعیت: سپتامبر ۲۰۲۶»). لینک رسمی را لحظه ساخت اسلاید چک کن.

### ۳.۲ FreeBuf
- **یافته:** FreeBuf (`freebuf.com`) **ابزار ایجنتی نیست**؛ رسانه/کامیونیتی بزرگ امنیت سایبری چین است (اخبار، تحلیل، رویداد). پس در جدول «ابزار» نباید ستون مستقل بگیرد.
- **پیشنهاد نقش (به‌جای حذف):** در بخش «امنیت و ایجنت» (مثال هک/دفاع) به‌عنوان **منبع** بیاید: «حمله و دفاع ایجنتی را کجا دنبال کنیم؟» + ۱ مثال تیتر. این هم خواسته کارفرما (پوشش امنیت) را نگه می‌دارد، هم خطای دسته‌بندی را اصلاح می‌کند. اگر کارفرما منظوش ابزار دیگری به نام FreeBuf بوده، بگوید تا اصلاح کنم.

### ۳.۳ لیست نهایی پیشنهادی (۸ ردیف برای بخش ابزارها)

| # | ابزار | نوع | نقش در ارائه |
|---|---|---|---|
| ۱ | **Hermes Agent** | ایجنت عمومی، اوپن‌سورس MIT، چندپروایدره | ستاره ارائه، مثال حلقه + MCP + حافظه |
| ۲ | **Claude Code** (Anthropic) | CLI کدنویسی، ترمینال‌محور | استاندارد صنعتی عامل کدنویسی |
| ۳ | **Cursor** | IDE ایجنتی (فورک VS Code) | تجربه روزمره برنامه‌نویس |
| ۴ | **OpenAI Codex** | CLI/ابری کدنویسی | نماینده اکوسیستم OpenAI |
| ۵ | **OpenCode** | اوپن‌سورس، ترمینال، چندمدله | گزینه hacker-friendly و قابل self-host |
| ۶ | **Devin** (Cognition) | عامل خودگردان وب | سقف ادعای autonomy (با قید نقد) |

## ۴. ستون فنی ارائه (متن خام فشرده برای اسلایدساز)

### ۴.۱ تعریف یک‌خطی (اسلاید ۱ بخش ایجنت)
> «چت‌بات **جواب** می‌دهد؛ ایجنت **کار** انجام می‌دهد: می‌فهمد، ابزار صدا می‌زند، نتیجه را می‌بیند، تا تمام شدن تکرار می‌کند.»

### ۴.۲ دیاگرام واحد حلقه (در هر سه مثال تکرار شود)
```
هدف (زبان طبیعی)
  → برنامه‌ریز (LLM: قدم بعدی چیست؟)
  → عمل (Tool/MCP: خواندن فایل، SSH، API رزرو...)
  → مشاهده (خروجی ابزار / خطا / نتیجه)
  → حافظه + تصمیم: تمام شد؟ اگر نه، برگرد به برنامه‌ریز
```
- ایجنت **مستقیم** اجرا نمی‌کند؛ به «میزبان» (مثل Hermes/Claude Code) می‌گوید اجرا کن، نتیجه را می‌خواند. (همان حرف دقیق کارفرما در پیام ۱۱:۱۸.)
- دو مفهوم اقتصادی: **پنجره کانتکست** (حافظه کوتاه، پول است) و **مهارت/حافظه بلند** (دفعه بعد ارزان‌تر).

### ۴.۳ MCP در یک پاراگراف (برای اسلاید)
> «MCP یعنی توافق مشترک که «هر سرویسی خودش را چطور به ایجنت معرفی کند»: چه کارهایی بلد است، چه ورودی می‌خواهد، چه خروجی می‌دهد. اگر هتل/ایرلاین/سرور MCP بدهد، هر ایجنتی (هرمس یا غیره) می‌تواند از آن استفاده کند. پس جنگ آینده بر سر «کی بهتر خودش را به ایجنت‌ها معرفی می‌کند» است.»

### ۴.۴ سه مثال (همان سه‌تایی کارفرما، با پرداخت یکدست)
۱. **کدنویسی:** خواندن پروژه → انتخاب فایل → ویرایش → تست/کامپایل → خواندن خطا → اصلاح → اتمام. نکته: تست و کامپایلر «داور بی‌رحم»‌اند و توهم را می‌گیرند.
۲. **دواپس (مثال مِتر/داکر کارفرما):** وصل SSH → `docker ps`؟ هست/نیست؟ → نصب/اجرا → لاگ → سالم؟ → اتمام. نکته: هر کاری که در ترمینال یا API شدنی است، در قلمرو ایجنت است.
۳. **سفر:** برنامه → جست‌وجوی پرواز → رزرو → اقامت → پرداخت → ایمیل/تفریح. شرط: سرویس مقصد MCP/API بدهد. جمله کلیدی کارفرما عیناً بماند: «منطقاً هیچ تفاوتی با برنامه‌نویسی نمی‌کند، فقط ابزار فرق می‌کند.»

### ۴.۵ بنچمارک و قیمت (روش، نه عدد حفظی)
- سه دسته بنچمارک معرفی شود: **کدنویسی** (SWE-bench و همتاها)، **دانش عمومی** (MMLU-style)، **عاملیت** (وظیفه چندمرحله‌ای با ابزار، مثل GAIA/τ-bench/Terminal-Bench-style). برای هرکدام فقط بگو «چه چیزی را می‌سنجد و چرا می‌شود به آن شک کرد» (آلودگی داده، مهندسی هارنس).
- قیمت: جدول را روز ساخت از OpenRouter/صفحه رسمی بردار و تاریخ بزن. در تحلیل عدد حفظی نمی‌نویسم تا دروغ نشود.
- استاندارد API: عملاً `chat/completions`-style اوپن‌ای‌آی استاندارد دفاکتو است؛ OpenRouter بروکر، HuggingFace میزبان مدل/دیتاست. همین دو خط در اسلاید کافی است.

### ۴.۶ آینده فنی (۴ خط)
- مدل‌ها کوچک‌تر و ارزان‌تر می‌شوند؛ بخشی روی گوشی می‌آید، ولی «پایان GUI» اغراق است — درستش: **«نقطه ورود از آیکون به گفتگو می‌رود؛ GUI برای مرور/تایید می‌ماند.»**
- تشبیه **DOS→Windows عیناً بماند** (دستور کارفرما): «سرویسی که خودش را برای ویندوز به‌روز نکرد روی DOS ماند و رفت؛ سرویسی که خودش را Agent-ready نکند می‌رود.»
- فرصت: «MCPایز کردن کسب‌وکارها» — بهترین فرصت نقدشونده امروز برای مخاطب ایرانی.

## ۵. طراحی برای مخاطب سه‌گانه (پاسخ به جواب ۴ و ۵)

- **هسته مشترک (همه):** مقدمه + حلقه ایجنت + سه مثال + آینده + مهارت (حدود ۶۰٪ اسلایدها، زبان ساده، طنز کنترل‌شده).
- **لایه عمیق (دانشجو + شرکت، علامت ⭐):** LLM زیر کاپوت، MCP فنی، جدول ابزارها، بنچمارک، امنیت (prompt injection، دسترسی بیش‌ازحد)، اقتصاد توکن. سخنران برای ورودی‌های جدید رد می‌شود، برای شرکت باز می‌کند.
- چون «زمان با سخنران است»، هر بخش یک اسلاید «نقشه و زمان پیشنهادی» داشته باشد (مثلاً: هسته ۹۰ دقیقه، عمیق ۶۰ دقیقه).

## ۶. فرمول‌های حساس (عیناً برای اسلاید — پاسخ به جواب ۶ و ۷)

۱. **قید ۹۰٪/۱۰٪ (زیر هر اسلاید عدد):**
> «عددهای ۹۰/۱۰ شهود سخنران است، پژوهش پشت آن نیست؛ جهت (شکاف برندگان/جاماندگان) جدی است، عدد را جدی نگیرید.» **نظر**: اینقدر بد و ناشیانه ننویس حیوون

۲. **قید پزشکی:**
> «پیش‌بینی حذف ۹۰٪ پزشکان، سناریوی شهودی است نه برآورد پژوهشی؛ آنچه پژوهش‌ها می‌گویند «درصد وظایف قابل‌اتوماسیون» است نه «درصد شغل‌های حذف‌شده». موانع اعتماد/مسئولیت/بیمه سرعت را کم می‌کند.» **نظر**: لازم نیست این چیزها رو بیاری اصلا. تو بنویس که پیش‌بینی اینه و دیگه توضیح نده که پژوهش‌ها چی میگن

۳. **حذف مخ‌زدن:** انجام شد — فقط معامله خریدار/فروشنده با مذاکره ایجنت‌به‌ایجنت و امضای انسانی.
