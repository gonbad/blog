# Issue 003 — Up/Down stop after clicking a slide control

Scope: helper
Project: 001-workshop-7 · 0.1.1

## Report
Up/Down stop after clicking a slide control

## Cause
The document key handler returned immediately for every focused button, link, summary and tab. Clicking a control kept focus there, so the presentation's vertical keys were never handled.

## Correction and verification
Keep editing/local-key controls exempt, preserve Space activation on interactive controls, and handle Up/Down/Page keys after ordinary control clicks. Move keyboard navigation focus to the selected section heading. Local browser regression checks now exercise clicked navigation, example and decision buttons, a download link, offline copy, native Space/tab behavior and text editing. Public deployment verification is recorded with the patch release.

## Reusable change
The publishing check procedure and Moom /issue procedure now require reproducing the actual focus state after interaction. This changes the navigation helper and its meaningful acceptance checks, not the content or the user's preferences.

Resolution: fixed and deployed as `0.1.1-1c43ab914ef6`. Public browser and offline regression checks passed; final frontend hashes match. See [verification](../versions/V0.1.1/releases/0.1.1/verification.json).
