# Journal migration to the current Kandoo method

The owner authorized migration in place and explicitly deferred physical relocation and
native-host rehearsal. This work replaces the retired workflow engine and its current
JSON state with constitutions, living Markdown and synchronized command procedures.
Historical requests, decisions, source snapshots, prior deployment receipts and the
pre-migration state are retained. Original roadmaps are archived; unresolved candidates
are carried into the current living roadmap.

Shared publishing/build/deployment implementation is in root kandoo/. Public source
selection is Project-owned living publication.md, and absent configuration means a
private draft. The existing six selected Projects build with five standalone archives.
The new private 006-independent-journal article previews without project.json. Its
technical and offline checks do not grant editorial acceptance or public publication.

The handbook owns its packaging helper, imported kit, browser verifier and pinned Node
dependencies. Other post verifiers belong to their Projects too. A copied Journal
builds using its committed imported material with no template/parent-tool dependency.
Deployment verifies its configured publication instead of an unrelated private service.

Installed bootstrap entries remain local recovery handoffs; canonical bootstrap docs
are absent. Close/reopen the host to discover the current commands. Native-host behavior,
new server provisioning and live deployment were not tested or represented as passed.
The owner will perform the native rehearsal; no synthetic host simulation remains.
